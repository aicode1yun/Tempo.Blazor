Stabilization baseline for the TmDocumentEditor plan. The previously reported

## Root cause found: HistorySave "flakiness" was a deterministic product bug

Commit `295b7020` (2026-06-19) deleted `src/Tempo.Blazor/wwwroot/js/document-editor.js`
together with its host `<script>` tags — but that file defined the
`window.tmDocumentEditor` browser global that `TmDocumentEditor.razor.cs` still
invokes for `enableBeforeUnloadGuard`, `disableBeforeUnloadGuard` and
`downloadFile`. Every interop call since then failed and was silently swallowed
by a `catch`, so:

- the before-unload guard never armed → both HistorySave guard tests failed
  every run (`getBeforeUnloadGuardState` returned `undefined`),
- **document file downloads (export) were silently broken in all hosts**,
- **offline draft persistence was silently broken**: `IndexedDbDocumentOfflineStore`
  invokes `tmDocumentEditor.offlineStore.*` and its safe-catch wrappers turned
  every IndexedDB call into a no-op. The offlineStore surface is restored in the
  same module and the service now imports it before the first call (covered by
  updated `IndexedDbDocumentOfflineStoreTests` + 2 more Node tests).

Fix (additive, no host markup needed): new ES module
`Tempo.Blazor.DocumentEditor/wwwroot/js/document-editor/interop/browser-globals.mjs`
installs the global idempotently; `TmDocumentEditor` imports it on first render
and before each guard/download interop call (import cache resets on failure so
prerender cannot poison it). Covered by 5 Node tests
(`interop/__tests__/browser-globals.test.mjs`) and 2 bUnit regression tests
(`TmDocumentEditorBeforeUnloadGuardTests`) — written red-first.

## Stability fixes applied in Phase 0

| Area | Fix | Class |
| --- | --- | --- |
| Before-unload guard + downloads | Restored `window.tmDocumentEditor` via self-installed ES module (see above) | `TmDocumentEditor` |
| HistorySave | Added `[TestInitialize]` server-state reset (`DocumentEditorE2EReset.ResetAsync`) so saved markers cannot accumulate in the persisted phase-12 document across tests/runs | `DocumentEditorCanvasHistorySaveE2ETests` |
| PDF search | Replaced `WaitForTimeoutAsync(600)` after next-match click with a deterministic counter-text-change expectation | `PdfViewerAnnotationsE2ETests` |
| Smoke probe | `/pdf-viewer` probe now waits for `.tm-pdf-viewer__canvas` (unconditional, proves PDF.js render) instead of the conditional `pdf-demo-selection` element | `SmokeLaneE2ETests` |
| Node tests | `scripts/run-node-tests.mjs` enumerates `*.test.mjs` explicitly (114 files / 498+5 tests verified) — a stale glob can no longer silently skip tests | package.json |

Reviewed but intentionally left as-is:

- `PdfAnnotatorE2ETests` (`WaitForTimeoutAsync(500)` before a
  negative assertion): a settle-wait before asserting that *nothing* appeared
  cannot cause a false failure; removing it would only weaken the assertion.
